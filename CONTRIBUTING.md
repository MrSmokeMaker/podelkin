# Contributing

Спасибо за интерес к «Рукоделию»! Гайд — для контрибьюторов любого уровня.

## Процесс PR

1. Форкните репозиторий и создайте ветку от `main`:
   `git checkout -b feat/kratkoe-nazvanie` (`feat/`, `fix/`, `docs/`).
2. Внесите изменения. Один PR — одна логическая единица работы.
3. Проверьте локально: `bun run lint` и `bun run build` — оба должны пройти.
4. Заполните чек-лист PR (шаблон появится автоматически; ориентир — ниже).
5. Откройте PR с понятным заголовком и описанием «что и зачем».
   Скриншот — если менялся UI.

## Код-стайл

- TypeScript strict: без `any`, без `@ts-ignore`. Типы для данных API —
  в месте объявления ответа.
- Стиль форматирования — Prettier: `bunx prettier --write .`.
- Компоненты — функциональные; `"use client"` только там, где есть состояние,
  эффекты или обработчики.
- Тексты интерфейса и ошибок — на русском, тон дружелюбный
  («Не удалось создать доску», а не «Error 500»).
- Цвета — только токены темы (`paper`, `ink`, `clay-soft`…), без сырых hex
  в компонентах. Layout mobile-first, цели касания от 48px.
- Комментарии — только для неочевидных «почему» (ограничения, инварианты).

## Тесты

Автоматических тестов пока нет — проверка сборки (`bun run build`,
включая type-check) обязательна. Перед PR вручную прогоните сценарий:

1. Поиск: `?q=свеча` находит и «свечку» (синонимы).
2. `/api/export/detailed.csv` без `role=premium` отдаёт 403.
3. Создание 4-й доски на free — понятная ошибка лимита.
4. Офлайн (DevTools → Offline): посещённые страницы открываются, мутации
   честно падают.

Для новой фичи добавьте такой ручной сценарий в описание PR.

## Чек-лист PR

- [ ] `bun run lint` и `bun run build` проходят без ошибок и предупреждений
- [ ] Нет `@ts-ignore`, `eslint-disable` и других отключённых проверок
- [ ] Новые premium-возможности закрыты фича-флагом + `PremiumBadge`
      + `disabled` (не спрятаны полностью)
- [ ] Серверная проверка прав дублируется на бэкенде (`getAuthUser`)
- [ ] Тексты — на русском; цвета — токены темы; mobile-first проверен
- [ ] Service worker не кэширует новые мутации (только GET)
- [ ] README обновлён, если менялся API или тарифы

## Где что лежит

| Путь | Назначение |
|---|---|
| `src/app/api/**/route.ts` | Route Handlers (бэкенд) |
| `src/lib/db.ts` | Слой данных в памяти (сид, модели) |
| `src/lib/feature-flags.ts` | Карта тарифов free/premium/admin |
| `src/lib/auth.ts` | Мок-аутентификация (точка для JWT/OAuth) |
| `src/data/mockData.ts` | Сид-данные: поделки, прайс-бук, запасы |
| `public/sw.js` | Service worker (кэш-стратегии) |

## Добавить поделку

Запись в `src/data/mockData.ts`: `slug`, `title`, `category`, `difficulty`,
`estimatedTimeMin`, шаги с `minutes`, материалы с количеством и единицами.
Цены материалов должны быть в прайс-буке — иначе стоимость посчитается
частично, а недостающие цены появятся в `missingPrices` (это допустимо,
но проверьте, что UI это показывает).
